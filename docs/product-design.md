# Body Park · 跳绳小挑战（Jump Rope Mini Challenge）产品设计

> 一句话定位：**打开就能跳的摄像头跳绳小游戏** —— 零学习成本、零配置，站到镜头前就开始，跳完自动打卡。
>
> 对标参考：任天堂 Switch《Jump Rope Challenge》的"极简 + 治愈 + 每日 100 下"。

---

## 1. 设计原则（核心诉求的翻译）

用户的核心诉求是"简单易上手，不用动脑，打开就能用"。落到设计上是三条铁律：

| 原则 | 具体含义 |
|---|---|
| **零决策启动** | 从打开到开始跳，用户不需要做任何选择。默认目标（首次 50，之后记住上次的选择），默认前置摄像头，站进人形框自动倒计时开始。 |
| **全程免触屏** | 跳绳时手里有绳，不可能碰屏幕。开始靠"站进框"，结束靠"达标自动结算"或"离开画面 5 秒自动暂停"。 |
| **反馈永远比数字先到** | 每一跳的音效/动效延迟控制在 100ms 以内。哪怕计数偶尔漏一两下，节奏感和愉悦感不能断。 |

## 2. 核心体验闭环（60 秒讲完的产品）

```
打开 App/Atom
   │
   ▼
今日页：吉祥物迎接 + 今日目标（50/100）+ 打卡条
   │  点「开始跳绳」（唯一大按钮）
   ▼
准备页：摄像头取景 + 人形轮廓框
   │  人站进框 → 自动 3·2·1 倒计时
   ▼
跳绳中：每跳 +1，大数字 + 吉祥物同步跳
   │  每 10 下触发一次小惊喜（换背景 / 加星 / 彩带）
   ▼
达标庆祝：满屏彩带 + 吉祥物庆祝动画
   │  自动进入
   ▼
结算页：本次成绩 + 星星收入 + 连续打卡天数 + 一键分享
   │
   ▼
明天再来（连续打卡 streak 是留存钩子）
```

## 3. 核心玩法

### 3.1 目标与计数
- **目标制**：50 次 / 100 次两档（Switch 同款心智），另留一个"自由跳"入口给想多跳的人。默认记住上次选择。
- **计数方式**：端上姿态估计（MoveNet / MediaPipe Pose 级别的轻量模型），取髋部/肩部关键点的**垂直方向周期性峰值**判定一次起跳，状态机去抖（防止原地晃动误计）。
- **计数反馈**：数字跳动 + 短促"叮"声 + 吉祥物同步弹跳。数字用超大字号（屏幕高度的 1/4），2 米外可读。
- **容错**：漏计不补、多计不扣 —— 这是自娱产品不是裁判，体验流畅 > 计数精确。

### 3.2 吉祥物（工作名：Bono，一只弹力球身材的小袋鼠）
- 跳绳中：跟着用户的节奏**同步蹦跳**，是"陪练"而不是装饰。
- 待机时：打瞌睡 / 拉伸热身，点它有彩蛋反应。
- 达标时：后空翻庆祝。
- 成长线：用星星兑换 Bono 的**换装**（帽子/眼镜/围巾）和**场景皮肤**，这是激励体系的消耗出口。

### 3.3 惊喜机制（可变奖励）
| 触发点 | 表现 |
|---|---|
| 每 10 下（固定节拍） | 背景渐变换色 + 上扬音效，让"再跳 10 下"永远有个小盼头 |
| 每 20 下 | +2⭐ 星星飘入右上角余额，伴随叮咚声 |
| 随机彩蛋（约 15% 概率挂在 10 的倍数上） | 双倍星星 / 彩带雨 / Bono 换个搞怪姿势 —— 不可预期的奖励是上瘾感的来源 |
| 达成目标 | 满屏庆祝 + 里程碑徽章（累计 1000 / 10000 下等） |

## 4. 激励机制

- **每日打卡**：跳满当日目标即打卡。首页常驻"连续 N 天"火苗 + 最近 7 天的打卡条。断签给一次"补签卡"（用星星兑换），降低挫败感。
- **星星（软货币）**：跳绳中掉落 + 达标奖励 + 连签里程碑（3/7/21 天）加成。消耗于：吉祥物换装、场景皮肤、补签卡。
- **实物/权益奖品（可选运营位）**：连续 21 天或月度累计榜，兑换 Body Park 周边或课程券 —— 放在结算页的"低调运营位"，不打扰核心闭环。
- **克制原则**：不做排行榜 PK、不做好友比拼（第一版）。这个产品的情绪基调是"治愈的自我坚持"，不是竞技。

## 5. 双端设计：手机 App vs Atom

| 维度 | 手机 App | Atom（智能便携设备） |
|---|---|---|
| 姿势 | 竖屏，手机立在地上/桌上，前置摄像头 | 横屏，设备摆在电视柜/地面，广角摄像头 |
| 观看距离 | 1.5–2 米 | 2–3 米 |
| 排版 | 竖向：计数在上，吉祥物在下 | 横向三栏：计数居中放到最大，吉祥物在侧 |
| 交互 | 触屏 + 站位触发 | 免触屏优先：站位触发 + 语音播报（"三、二、一，跳！"） |
| 数据 | 同一账号，打卡与星星**双端同步** | 同左；Atom 端结算页出二维码，手机扫码看详情/分享 |

设计策略：**一套设计语言、两套排版**。组件（计数器、进度环、打卡条、吉祥物）完全复用，只改布局。

## 6. 关键技术点（供研发评估）

1. **姿态估计**：端上推理，MoveNet Lightning 级别（>30fps on 中端手机）；Atom 若有 NPU 则跑更高精度模型。
2. **跳跃判定**：髋部关键点 y 坐标做带通滤波 → 峰值检测 → 状态机（腾空/落地）；典型跳绳频率 1.5–3 次/秒，以此设频率窗口过滤误判。
3. **延迟预算**：摄像头采集→推理→计数→音效反馈全链路 < 100ms，音效走低延迟通道（iOS: AVAudioEngine；Android: AAudio/Oboe）。
4. **隐私**：视频帧全部端上处理，**不上传任何影像**，只上传计数结果。首次启动用一句话讲清楚（这也是家长关心点）。
5. **弱光/遮挡兜底**：置信度连续走低时，UI 提示"往后站一点/开个灯"，而不是默默漏计。

## 7. MVP 范围建议（先跑通闭环，两周可 demo）

**做**：今日页、准备页、跳绳中（计数 + 每 10 下换背景 + 音效）、达标庆祝、结算页、本地打卡记录、吉祥物基础动画（待机/跳/庆祝三态）。

**不做（第二期）**：星星商城与换装、补签卡、实物奖品运营位、Atom 端语音播报、分享海报。

衡量指标：D1/D7 留存、日均完成率（开始跳的人里跳满目标的比例）、单次时长。核心假设是"**打卡 streak + 吉祥物养成**能把一个 3 分钟的小工具变成每日习惯"。
