## 1. 背景与机会

Body Park 的智能便携设备 **Atom**（466×466 圆形 LCD + 摄像头 + 后端 AI 姿态识别管线）需要一个"打开就能用"的高频轻运动应用。跳绳（无绳模拟跳）是理想切入点：动作标准化、AI 计数成熟、单次 1–5 分钟、老少皆宜，且有任天堂《Jump Rope Challenge》验证过的极简玩法范式。

**核心诉求（不可妥协）：简单易上手，不用动脑，打开就能用。**

## 2. 目标与范围

### 2.1 本期目标（P0）
1. 用户从系统入口卡到开跳 **≤ 3 次点按、≤ 10 秒**；
2. 建立"每天来跳一下"的留存钩子：连胜打卡 + 每日重置排行榜；
3. 训练过程反馈爽：打击感计数、实时骨骼火柴人 + 虚拟绳、金色涟漪、燃起来背景，全部在 10–15fps 下成立。

### 2.2 非目标（明确不做 / 暂缓）
| 项 | 状态 |
|---|---|
| 手机 App 端 | 暂缓（设计保留在设计文档，不开发） |
| 多用户/家庭账号 | P1（PRO 方向），本期单账号 |
| 勋章/成就体系 | P1 暂缓（规则已设计，见设计文档 §勋章），先聚焦打卡 + 排行 |
| 周联赛分组、亲友 PK | P2 |
| 首次引导教程 | 不做主线（产品自解释 + 语音引导兜底） |
| 手表/心率接入 | P2（卡路里先用 MET 估算） |

## 3. 用户与场景

- **主用户**：6–17 岁青少年（体测刚需）+ 家庭成人用户；单设备单账号。
- **场景**：客厅/房间，设备摆在 1–2 米外，用户站在镜头前无绳跳。全程手里"有绳"，**屏幕不可触碰是常态**——屏上按钮只做次要入口，主流程靠自动化 + 语音。

## 4. 信息架构与页面流转

```
Atom OS 系统入口卡（Bono + 连续 N 天）
   │ 点按
   ▼
首页卡组（横滑 3 页，圆点指示 + 边缘箭头可点）
   ├─ Page1 首页：连续 N 天(大字行) / 今日 / PB 行 / 累计天数+★ / [Start] [⚙]
   │     区块直达：连胜→打卡记录页②，今日→排行榜②，PB→最佳战绩②，累计→打卡记录②
   ├─ Page2 打卡记录：周点 + 近 5 天 + 近 7 天小结 + [查看全部→②]
   └─ Page3 全球排行：Top3 + 我 + 超越目标 + [完整榜单→②]
   │
   │ Start
   ▼
模式选择（两个大选项卡：限时跳 / 不限时；副文案带个人化数据）
   │ 选任一模式（无站位校验）
   ▼
3 · 2 · 1 · BodyPark（品牌发令帧 0.75s）
   ▼
训练屏（详见 §5.4）──离开画面→暂停(5s 未回自动结算)──30min 提醒/60min 强制结算
   ▼
达标庆祝（不打断计数，仅结束时全屏庆祝）
   ▼
结算页（成绩面 ⇄ 分享二维码面，点按翻面；45s 无操作回首页）
```

二级页（全屏覆盖层，点按空白处返回）：打卡记录、排行榜（全球/同城）、最佳战绩、设置。

## 5. 功能需求

### 5.1 系统入口卡 & 首页
| # | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | 入口卡展示 Bono、应用名、连续打卡天数 | 点按任意处进入首页 |
| FR-1.2 | 首页数据行（自上而下）：`连续 N 天`（标签+56px 大数+标签一行式）→ `今日 X 下`（居中）→ PB 行（PB 徽章+单轮最佳 ｜ 1' 最佳，左右对齐+分隔线）→ `累计 N 天 ★M`（左右对齐+分隔线） | 数据实时正确；每个区块可点按直达对应二级页；按压有直切反馈 |
| FR-1.3 | 底部 Start 主按钮（≥80px 高）+ 设置圆钮 | Start→模式选择；⚙→设置页 |
| FR-1.4 | 卡组横滑 + 圆点指示 + 两侧箭头（可点按翻页）；未滑动过时右箭头脉动 + 进入首页时卡组"探头"引导 | 滑动阈值 40px；滑动后引导消失 |

### 5.2 模式选择
| # | 需求 | 验收标准 |
|---|---|---|
| FR-2.1 | 两个大选项卡：**限时跳**（时钟图标）/ **不限时**（∞图标） | 图标为单色 SVG；选项卡带按压反馈 |
| FR-2.2 | 副文案单行、个人化：限时=`N 分钟倒计时 · 最佳 X`；不限时=`每日任务 N · 今日 X` | 不折行；数据实时 |
| FR-2.3 | 选择即开跳（无站位校验），返回钮回首页 | 点选后 ≤300ms 进入倒计时 |

### 5.3 开跳流程
| # | 需求 | 验收标准 |
|---|---|---|
| FR-3.1 | 倒计时 3·2·1（136px 大数字 + 哔声 + 语音报数），间隔 900ms | — |
| FR-3.2 | 发令帧：品牌口号 **BodyPark**（品牌绿 56px）停留 0.75s，语音喊 "Body Park!"，然后进入训练屏并开始计时 | 双语语音都喊 Body Park |

### 5.4 训练屏（核心）
| # | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | **布局**：贴边进度环（r=226，线宽 13）→ 顶部计时（距上缘 4.6%）→ 上 1/3 打击计数 → 下 2/3 实时骨骼火柴人 | 图层不互相遮挡 |
| FR-4.2 | **计数动画**：每跳数字砸入-压缩-回弹（0.26s 离散帧）；逢十重击版（1.9× + 横向震动 0.4s）；音效为五声音阶循环叮声 | 计数、动画、涟漪、音效同帧触发 |
| FR-4.3 | **骨骼渲染**：AI 喂入 33 点（MediaPipe 拓扑，归一化坐标，≥15Hz）→ 等宽直杆火柴人（浅白肢体+纯白头/手/脚圆头）；整帧固定缩至 2/3、底边锚定 0.94（顶部 1/3 永久让给数字）；线宽随肩宽缩放（0.55–1.5×）；500ms 无数据回落内置模拟 | 渲染延迟 <100ms；无肩髋凸起、无梯形躯干 |
| FR-4.4 | **虚拟绳**：翠绿色，相位振荡器驱动，转速=实测跳频 EMA；每次计数把相位向"绳过脚下"软校正 40%；绳过下半周画在人前/上半周在人后；3 条残影弧抗低帧率频闪；不跳时淡出（1.2s 全显 + 0.7s 淡出） | 绳与跳跃节拍视觉同步 |
| FR-4.5 | **触地涟漪**：仅在"判定计数落地"触发；单个透视椭圆环；0 帧最强（金色闪光 + 最粗线宽），0.7s 内爆发扩张-压缩-回弹-消失，与计数动画同一套"打击语法" | 无计数不出现 |
| FR-4.6 | **进度环与星**：一圈=一个目标（自由跳 50），跳满清零重画；每满一圈计数旁 +1 颗 ★（>4 颗收敛为 ★×N） | 限时模式下环变为剩余时间消退 |
| FR-4.7 | **燃起来**：前 50 纯黑背景；每满 50 火焰升一级（暖橙放射光，3 级封顶，带脉冲） | 15fps 下用 steps() 量化旋转 |
| FR-4.8 | **达标不打断**：达到目标时彩带 + toast + 数字转暖色，继续 51、52… 往上数 | 绝不弹结算 |
| FR-4.9 | **限时测试**：顶部倒计时读秒（最后 10s 转暖橙）；剩 30s/10s 语音节点；时间到自动结算并记历史最佳 | 1'/2' 分别记最佳 |
| FR-4.10 | **暂停**：离开画面（AI `setPresence(false)`）立即暂停+停表，遮罩带"继续/立即结算"；5s 未回自动结算 | 暂停时长不计入用时与卡路里 |
| FR-4.11 | **激励事件**：整 10 报数/换景、整 20 星星+2（15% 概率彩蛋双倍）、每日隐藏数字（55–99）踩中 +5★、实时超越播报（超过对手即时 toast，进前三/登顶语音） | 语音分层：整十报数、整三十鼓励、满圈报星 |

### 5.7 AI 教练语音
开场即倒计时报数；整十报数（≤3 字）、整三十带一句鼓励、满圈报星、达标/破纪录庆祝、隐藏数字彩蛋、超越播报、30 分钟休息提醒、收尾总结。原则：**短句、低频、可关闭**；高频短句用预生成语音包，动态内容 TTS。详见设计文档 §3.5。

## 6. 状态策略（空 / 边界 / 极限）

| 类 | 策略 |
|---|---|
| 空状态 | 首页显示真实零值（连续 0 天 / 今日 0 / PB —）；记录页"还没有记录，跳一轮就有啦"；榜单未跳也给真实名次与够得着的目标 |
| 计数累积 | **单轮从 0 起算**（一轮一个目标）；**今日累计跨轮累加**（首页/榜单/打卡/结算"今日累计"行），0 点重置 |
| 超时链路 | 开跳无站位校验；跳绳中离开→立即暂停，5s 未回→自动结算；结算页 45s 无操作→回首页；首页长期无人交给系统层息屏 |
| 极限保护 | 单轮 30min 语音提醒休息、60min 强制结算（儿童过练保护，成绩照常落档）；计数 ≥1000 数字 96→68px 降档；★>4 收敛 ★×N；单日封顶 3000（服务端防刷） |

## 7. 非功能需求

| 项 | 标准 |
|---|---|
| 屏幕 | 466×466 圆形，内容必须在内切圆安全区内；页面骨架：标题钉顶部（≤5 汉字/8 词符）、内容中区、提示钉底部 7.5%（≤22px 单行） |
| 帧率 | 10–15fps 波动；动效全部状态直切 + steps() 量化；不依赖 transition |
| 字号 | **6 档标准：18/22/24/28/32/36**（微标注/辅助/正文/强调/标题/庆祝）；大数字为独立展示档 40/56/68/96/136，不占文字标准；以 CSS token 落地，禁止档外字号 |
| 品牌 | 黑白灰绿（绿 #23C766 唯一活力色）+ 打击金（涟漪/重击帧）；图标一律单色 SVG，禁 emoji |
| 双语 | 全部文案（含语音/toast）收敛到 I18N 字典；EN 为讨论主版本；语音音色随语言切换 |
| 反馈延迟 | 计数→动画/音效 <100ms；骨骼渲染 <100ms |
| 隐私 | 摄像头画面不上屏、不存储、不上传；只上传骨骼/计数结果 |

## 8. 数据与接口

### 8.1 AI 管线 → 应用（固件桥）
| 接口 | 说明 |
|---|---|
| `feedPose(pts[33])` | MediaPipe Pose 拓扑,归一化 0–1,喂入前完成镜像,≥15Hz |
| `onJump()` | 一次有效跳跃判定 → 计数+1,同帧触发动画/涟漪/音效 |
| `setPresence(bool)` | 仅用于训练中暂停/恢复（不再作为开跳门槛） |
| 出向事件 | `session_start / jump{count} / session_end{count,ms,goal,testMin,kcal,newBest}` → 上报后端 |

WebView 版接口详表见 [`embedded/README.md`](../embedded/README.md)；纯 C 参考实现见 [`firmware/`](../firmware/)。**计数精度由 AI 团队保障，应用层不做判定、漏计不补多计不扣。**

### 8.2 本地档案（单账号）
`streak, lastDone, history{date:{count,ms,done}}, total, stars, bestSession, bests{1,2}, goalNum, testMin, age, weight, remind, luckyHits, scenes, outfit`

### 8.3 排行榜服务（后端）
结算上报 `{userId,date,count,ms,mode,city}`；Redis ZSET 按 `榜单×日期×地区` 建 key（`ZINCRBY/ZREVRANK/ZRANGE`），TTL 实现日重置；防刷：置信度分 + 单日 3000 封顶 + >8 跳/秒剔除 + 影子封禁。弱网缓存上次榜单、异步上报。

### 8.4 卡路里 & 体测评级
- MET 法：跳频 <100→8.8 / ≤120→11.8 / >120→12.3；kcal = MET × 体重 × 净跳时长（暂停不计）。
- 体测评级（仅 1 分钟测试）：按年龄段 5 档阈值出 及格/良好/优秀/满分。**⚠ 当前阈值为示意，上线前必须替换《国家学生体质健康标准》官方分表（年级×性别）。**

## 11. 里程碑建议

1. **M1 设计还原**：设计师按本 PRD + UI 界面图 + 原型产出高保真（重点：Bono 正式形象、燃起来背景、分享海报）；
2. **M2 端上开发**：固件团队基于 `firmware/` C 参考或 `embedded/` WebView 方案二选一落地；AI 管线联调（骨骼坐标系、计数同帧反馈）；
3. **M3 服务端**：排行榜 + 档案云同步 + 推送（连胜提醒）；
4. **M4 内测**：儿童/成人实测计数体感、语音节奏、15fps 动效验收。

## 12. 开放问题

1. Bono 正式形象与命名（当前为工作稿火柴人）；
2. 分享海报落地页（二维码指向的 H5）归属与排期；
3. 提醒推送通道（设备端 or 手机 App or 微信服务号）；
4. 同城榜的城市定位方案（IP 粗定位 vs 用户自选）；
5. 隐藏数字/彩蛋的概率与经济数值需数值同学复核（当前:20 下+2★、彩蛋 15% 双倍、隐藏数字+5★、达标+10★）。
