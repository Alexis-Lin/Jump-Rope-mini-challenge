## 1. 背景与机会

Body Park 的智能便携设备 **Atom**（466×466 圆形 LCD + 摄像头 + 后端 AI 姿态识别管线）需要一个"打开就能用"的高频轻运动应用。跳绳（无绳模拟跳）是理想切入点：动作标准化、AI 计数成熟、单次 1–5 分钟、老少皆宜，且有任天堂《Jump Rope Challenge》验证过的极简玩法范式。

**核心诉求（不可妥协）：简单易上手，不用动脑，打开就能用。**

## 2. 目标与范围

### 2.1 本期目标（P0）
1. 用户从系统入口卡到开跳 **≤ 3 次点按、≤ 10 秒**；
2. 建立"每天来跳一下"的留存钩子：连胜打卡 + 每日重置排行榜；
3. 训练过程反馈爽：打击感计数、实时骨骼火柴人 + 虚拟绳、金色涟漪、燃起来背景，全部在 10–15fps 下成立。

### 2.2 非目标（明确不做 / 暂缓）
| 项 | 状态 |
|---|---|
| 手机 App 端 | 暂缓（设计保留在设计文档，不开发） |
| 多用户/家庭账号 | P1（PRO 方向），本期单账号 |
| 勋章/成就体系 | P1 暂缓（规则已设计，见设计文档 §勋章），先聚焦打卡 + 排行 |
| 周联赛分组、亲友 PK | P2 |
| 首次引导教程 | 不做主线（产品自解释 + 语音引导兜底） |
| 手表/心率接入 | P2（卡路里先用 MET 估算） |

## 3. 用户与场景

- **主用户**：6–17 岁青少年（体测刚需）+ 家庭成人用户；单设备单账号。
- **场景**：客厅/房间，设备摆在 1–2 米外，用户站在镜头前无绳跳。全程手里"有绳"，**屏幕不可触碰是常态**——屏上按钮只做次要入口，主流程靠自动化 + 语音。

### 5.4 训练屏（核心）
| # | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | **布局**：贴边进度环（r=226，线宽 13）→ 顶部计时（距上缘 4.6%）→ 上 1/3 打击计数 → 下 2/3 实时骨骼火柴人 | 图层不互相遮挡 |
| FR-4.2 | **计数动画**：每跳数字砸入-压缩-回弹（0.26s 离散帧）；逢十重击版（1.9× + 横向震动 0.4s）；音效为五声音阶循环叮声 | 计数、动画、涟漪、音效同帧触发 |
| FR-4.3 | **骨骼渲染**：AI 喂入 33 点（MediaPipe 拓扑，归一化坐标，≥15Hz）→ 等宽直杆火柴人（躯干宽 = 2×腿宽，浅白肢体+纯白头/手/脚圆头，手圆头直径 = 臂宽不外凸，规格见[火柴人渲染说明](figure-rendering.md)）；整帧固定缩至 2/3、底边锚定 0.94（顶部 1/3 永久让给数字）；线宽随肩宽缩放（0.55–1.5×）；500ms 无数据回落内置模拟 | 渲染延迟 <100ms；无肩髋凸起、无梯形躯干 |
| FR-4.4 | **虚拟绳**：**绳色随机**——8 色池（默认翠绿），开轮随机抽色、**每满一圈换新色**（与燃起来升级同拍，构成课中小惊喜）；相位振荡器驱动，转速=实测跳频 EMA；每次计数把相位向"绳过脚下"软校正 40%；绳过下半周画在人前/上半周在人后；3 条残影弧抗低帧率频闪；不跳时淡出（1.2s 全显 + 0.7s 淡出） | 绳与跳跃节拍视觉同步 |
| FR-4.5 | **触地涟漪**：仅在"判定计数落地"触发；单个透视椭圆环；0 帧最强（金色闪光 + 最粗线宽），0.7s 内爆发扩张-压缩-回弹-消失，与计数动画同一套"打击语法" | 无计数不出现 |
| FR-4.6 | **进度环与星**：环一圈=一个目标（自由跳 50），跳满清零重画；**★ 固定每 50 一颗**（荣誉刻度全模式统一，与环解耦；燃起来火焰同拍），>4 颗收敛为 ★×N | 限时模式下环切换为时间刻度环（见 FR-4.9） |
| FR-4.7 | **燃起来**：前 50 纯黑背景；每满 50 火焰升一级（暖橙放射光，3 级封顶，带脉冲） | 15fps 下用 steps() 量化旋转 |
| FR-4.8 | **达标不打断**：达到目标时彩带 + toast + 数字转暖色，继续 51、52… 往上数 | 绝不弹结算 |
| FR-4.9 | **限时测试（1'/2'，默认 1' 主推）**：环变为 **60 格时间刻度环**（每格=总时长/60：1'=1 秒/格、2'=2 秒/格；逢五长刻度，表盘感；剩余=亮格从尾端逐格熄灭，最后 10s 剩余刻度转暖橙——离散熄灭天然适配 15fps）；顶部倒计时读秒（最后 10s 转暖橙）；剩 30s/10s 语音节点；时间到自动结算并记历史最佳 | 1'/2' 分别记最佳、分别成榜 |
| FR-4.10 | **暂停**：离开画面/切后台（AI `setPresence(false)`）立即暂停+停表，遮罩带"继续/立即结算"；**离开超过 3 分钟自动结算**（对齐课程通用出框策略；参数可配 3–5min） | 暂停时长不计入用时与卡路里；成绩照常落档 |
| FR-4.11 | **激励事件**：整 10 报数 + 数字重击闪 + **火柴人全身金光闪烁 0.5s** + 50% 概率飘少量庆祝彩带、整 20 星星+2（15% 概率彩蛋双倍）、每日隐藏数字（55–99）踩中 +5★、实时超越播报、节奏变慢轻推（每轮最多一次） | **常规节点不弹 toast（全语音化，不打扰画面）**；toast 仅限稀有事件：彩蛋双倍/隐藏数字/达标/超越/时长上限；语音分层：整十报数、整三十鼓励与纠错指导五五开、满圈报星 |
| FR-4.12 | **动作纠错反馈**（评审会新增）：AI 识别交替跳/单脚跳 → 不计数 + 教练语音提醒（"双脚并拢跳"）；接口 `formHint(alternating / single_foot / low_jump)`；识别能力 ≤3 跳/秒；正对/侧对均支持、引导正对；no-count 与严格度规则由 AI 团队出清单（开放问题 #7） | 同类提醒 ≥20s 间隔，不刷屏 |
| FR-4.13 | **自由跳时长上限**（会后定稿）：单轮上限 **15 分钟**（可配 10/15），最后 1 分钟语音预告（"还有一分钟到上限，冲刺！"），届满自动结算；替代原 30/60min 保护（限时模式本身 1'/2' 不需要） | 成绩照常落档 |
| FR-4.14 | **训练 BGM**（会后新增）：轻量节奏型循环（≈110BPM，极低音量垫在音效下，五声音阶低音与计数叮声同调式）；仅训练中播放，暂停静音、结算即停；设置可关；正式音源与音效包一起新制（不复用课程音效） | 不盖过语音与计数音效 |

### 5.7 AI 教练语音
**开场白（进入 APP 时播报，模块化拼装）**：称呼欢迎（有昵称才点名；未填昵称用无称呼欢迎语——评审会定稿）→ 第 N 次跳绳 → 历史数据亮点 1 条（连胜 / 昨日成绩 / 单轮 PB / 累计，按轮次轮换）→ 今天日期 → 目标召唤（4 条池按日轮换，如"目标 100 下，我们来试一下！"）。首次使用播新手版（自我介绍 + 日期 + 目标）；**同一天再次进入只播简短版**（"又来啦！今天已经跳了 128 下，再来一轮？"）。开场白只在首页播，开跳流程保持 3·2·1·BodyPark 即时开始，不被阻塞。

课中：倒计时报数；整十报数（≤3 字）、整三十**鼓励与纠错指导五五开**（指导池：膝盖微弯轻落地/前脚掌落地/手腕发力/目视前方/呼吸节奏）、满圈报星、达标/破纪录庆祝、隐藏数字彩蛋、超越播报、**节奏变慢轻推**（比本轮最快慢 60% 以上时"别停，跟上 Bono"，每轮最多一次）、15 分钟上限前 1 分钟预告、**破纪录追逐**（自由跳距历史最佳 ≤10 下播报"只差 N 下"，超越瞬间语音+金光+彩带+toast，结算必出庆祝页）、收尾总结。原则：**短句、低频、可关闭**；高频短句用预生成语音包，动态内容 TTS。详见设计文档 §3.5。

## 6. 状态策略（空 / 边界 / 极限）

| 类 | 策略 |
|---|---|
| 空状态 | 首页显示真实零值（连续 0 天 / 今日 0 / PB —）；记录页"还没有记录，跳一轮就有啦"；榜单未跳也给真实名次与够得着的目标 |
| 计数累积 | **单轮从 0 起算**（一轮一个目标）；**首页"今日累计"= 全模式当日总和**（跨轮累加，0 点重置）；打卡记录按天显示当日累计（轮数仅后台数据）；**榜单取单轮最高**（累计只做展示不上榜） |
| 超时链路 | 开跳无站位校验；跳绳中离开/切后台→立即暂停，**超 3 分钟未回→自动结算**（对齐课程出框策略，可配 3–5min）；结算页 45s 无操作→回首页；首页长期无人交给系统层息屏 |
| 极限保护 | 自由跳单轮上限 15 分钟（FR-4.13，成绩照常落档）；计数 ≥1000 数字 96→68px 降档；★>4 收敛 ★×N；单日封顶 3000（服务端防刷） |

# Body Park · 跳绳小挑战（Jump Rope Mini Challenge）产品设计

> 一句话定位：**打开就能跳的摄像头跳绳小游戏** —— 零学习成本、零配置，站到镜头前就开始，跳完自动打卡。
>
> 对标参考：任天堂 Switch《Jump Rope Challenge》的"极简 + 治愈 + 每日 100 下"。

---

## 1. 设计原则（核心诉求的翻译）

用户的核心诉求是"简单易上手，不用动脑，打开就能用"。落到设计上是三条铁律：

| 原则 | 具体含义 |
|---|---|
| **零决策启动** | 从打开到开始跳，用户不需要做任何选择。默认目标（首次 50，之后记住上次的选择），默认前置摄像头，站进人形框自动倒计时开始。 |
| **全程免触屏** | 跳绳时手里有绳，不可能碰屏幕。开始靠"站进框"，结束靠"达标自动结算"或"离开画面 5 秒自动暂停"。 |
| **反馈永远比数字先到** | 每一跳的音效/动效延迟控制在 100ms 以内。哪怕计数偶尔漏一两下，节奏感和愉悦感不能断。 |

## 2. 核心体验闭环（60 秒讲完的产品）

```
打开 App/Atom
   │
   ▼
今日页：吉祥物迎接 + 今日目标（默认 100，可设置）+ 打卡条
   │  点「开始跳绳」（唯一大按钮）
   ▼
准备页：摄像头取景 + 人形轮廓框
   │  人站进框 → 自动 3·2·1 倒计时
   ▼
跳绳中：每跳 +1，大数字 + 吉祥物同步跳
   │  每 10 下触发一次小惊喜（换背景 / 加星 / 彩带）
   │  达标时彩带庆祝但【不打断】——数字变绿，51、52……继续往上数
   ▼
用户自己停下（离开画面 5 秒 / 主动点结束）
   ▼
结算页：本次成绩（含超额）+ 星星收入 + 连续打卡天数 + 一键分享
   │
   ▼
明天再来（连续打卡 streak 是留存钩子）
```

## 3. 核心玩法

### 3.1 目标与计数
- **目标制**：默认 **100 次起**（JRC 同款心智），设置项中可按 50 步进自定义（预设 100/200/300 + 自由跳），默认记住上次选择。达标不打断，继续往上数。
- **课中计时**：跳绳中显示已用时（二级信息，放在计数下方原副标位置），暂停自动停表；结算页展示总用时。
- **1 分钟限时测试**（对齐国内体测标准项目）：目标选项中的独立模式。顶部计时改为**倒计时读秒**（最后 10 秒转暖色），环形进度改为**时间消退**；语音节点：开场"全力以赴"、剩 30 秒、最后 10 秒冲刺；时间到自动结算，记录**历史最佳**并播报"新纪录"。
- **计数方式**：端上姿态估计（MoveNet / MediaPipe Pose 级别的轻量模型），取髋部/肩部关键点的**垂直方向周期性峰值**判定一次起跳，状态机去抖（防止原地晃动误计）。
- **计数反馈**：数字跳动 + 短促"叮"声 + 吉祥物同步弹跳。数字用超大字号（屏幕高度的 1/4），2 米外可读。
- **容错**：漏计不补、多计不扣 —— 这是自娱产品不是裁判，体验流畅 > 计数精确。

### 3.2 吉祥物（工作名：Bono，一个可爱的小火柴人）

**品牌视觉基调：黑白灰绿。** 黑色线条 + 白色留白 + 灰阶层次，绿色是唯一的活力色，所有界面元素（按钮、进度环、状态灯、彩带）都收敛在这四色内。

- 形象：白色大圆脑袋 + 黑色火柴人线条身体，头顶一株**小绿芽**、绿色小手套和小绿鞋是仅有的品牌色点缀 —— 极简、成本低、动画好做，也和"运动线条感"天然契合。
- 跳绳中：跟着用户的节奏**同步蹦跳**（手里有一根绿色的绳），是"陪练"而不是装饰。
- 待机时：打瞌睡 / 拉伸热身，点它有彩蛋反应。
- 达标时：后空翻庆祝。
- 成长线：累计跳数解锁**换装**（发带/墨镜/围巾/皇冠/头盔，配色同样收敛在黑白灰绿 + 银），首页左右切换；场景皮肤按达标次数解锁。

### 3.3 惊喜机制（可变奖励）
| 触发点 | 表现 |
|---|---|
| 每 10 下（固定节拍） | 背景渐变换色 + 上扬音效，让"再跳 10 下"永远有个小盼头 |
| 每 20 下 | +2⭐ 星星飘入右上角余额，伴随叮咚声 |
| 随机彩蛋（约 15% 概率挂在 10 的倍数上） | 双倍星星 / 彩带雨 / Bono 换个搞怪姿势 —— 不可预期的奖励是上瘾感的来源 |
| 达成目标 | 满屏庆祝 + 里程碑徽章（累计 1000 / 10000 下等） |

### 3.4 每天来都不一样（新鲜感系统）

打卡产品最大的敌人是"腻"。新鲜感按实现成本分四层，逐层叠加：

| 层 | 内容 | 成本 |
|---|---|---|
| **① 日期可算层**（零成本，离线可算） | **月相**（阴晴圆缺真实计算，待机页展示）；每日问候语/教练开场白轮换；**今日主打场景**（六个场景每天轮换主推）；**每日隐藏数字**（55–99 之间每天一换，跳到正好踩中 → 彩带 + 加星，"不知道藏在哪"本身就是钩子）；周末/节气问候 | 无 |
| **② 数据层**（接 API） | **当地天气**驱动场景与 Bono 状态：雨天 Bono 打伞待机、雪天场景飘雪、高温天提醒补水；日出日落时间驱动昼夜配色 | 天气 API |
| **③ 运营层** | 节日限定装扮与场景（春节舞狮 Bono、万圣节南瓜头）；周末双倍星星；每月主题挑战（"三月累计 3000 下"） | 运营配置 |
| **④ AI 层** | 每日不同的**教练开场白与结算点评**，由 LLM 结合你的数据生成（"昨天你 3 分钟跳了 120，今天试试 130？"），永不重样 | LLM 调用 |

原型已实现第①层全部内容。原则：新鲜感元素只做"锦上添花"，不改变核心操作路径——每天打开的动作永远一样，变的是气氛和彩蛋。

### 3.5 AI 语音指导

**要做，但克制。** 跳绳时用户看不了小字，语音是 Atom 小屏的天然带宽；但话多了会烦，原则是**短句、低频、有信息量**：

| 时机 | 内容 | 例句 |
|---|---|---|
| 开场 | 每日不同的开场白（AI 生成） | "昨天的纪录，今天来打破它" |
| 倒计时 | 三、二、一，跳 | — |
| 整 10 | 只报数（≤3 字） | "四十" |
| 整 30 | 报数 + 一句鼓励 | "六十，节奏很稳！" |
| 整 50 | 点亮一颗星 | "一百下，点亮第二颗星！" |
| 达标 | 庆祝 + 引导继续 | "目标达成！继续保持！" |
| 隐藏数字 | 惊喜播报 | "踩中今天的隐藏数字！" |
| 节奏异常 | 变慢/停顿时轻推（每轮最多一次） | "别停，跟上 Bono！" |
| 收尾 | 数据总结 + 明日钩子 | "一共 105 下，比昨天多 12 下，明天见！" |

**不做**：每跳都出声、超过 8 个字的长句（跳起来听不进）、说教式纠错、不可关闭的语音。

**音色建议**：默认「**元气教练**」——明亮偏年轻的女声，语速稍快、句尾上扬，符合"陪练"人设；可选「温柔陪伴」（晚间自动切换）、「沉稳教练」；儿童模式默认「Bono 童声」（卡通变声处理）。选型三标准：短句爆发力、中文自然度、端侧合成延迟 < 300ms。

**技术方案**：高频固定短句（报数/倒计时/常用鼓励）**预生成语音包**内置，零延迟零成本；动态内容（个性化开场白、结算点评）用 TTS 实时合成，文案由 LLM 按用户数据每日生成。原型阶段用系统 TTS 模拟（自动优选中文音色，可在控制条开关）。

## 4. 激励机制

- **每日打卡**：跳满当日目标即打卡。首页常驻"连续 N 天"火苗 + 最近 7 天的打卡条。断签给一次"补签卡"（用星星兑换），降低挫败感。
- **星星（软货币）**：跳绳中掉落 + 达标奖励 + 连签里程碑（3/7/21 天）加成。消耗于：吉祥物换装、场景皮肤、补签卡。
- **实物/权益奖品（可选运营位）**：连续 21 天或月度累计榜，兑换 Body Park 周边或课程券 —— 放在结算页的"低调运营位"，不打扰核心闭环。
- **排行榜（独立模块）**：核心设计目标是**排名永远爬得动**——用户最怕"永远是那个名次"。四层机制保证可爬升：
  1. **每天 0 点重置**的日榜（全球 / 同城两个 Tab）：人人每天从 0 开始，跳就会升，绝无死榜；
  2. **邻近区间展示**：榜单只显示 Top 3 + 你的上下一名，配一句"再跳 N 下超过 XX"——把抽象排名变成够得着的下一个小目标；
  3. **实时超越反馈**：跳绳过程中每超过一位对手即时提示（"超过 Rocket_Ninja！全球第 12 名"），进前三/登顶有语音播报——排名的爬升感在课中直接兑现；
  4. **周联赛分组**（二期，Duolingo 模式）：每周把活跃度相近的 ~30 人分进一个小组，组内排名 + 周末升降级（青铜→白银→黄金…），彻底解决"高手垄断"。
- **竞技的克制**：不做 all-time 总量榜（劝退新人）；只比数字不做社交对抗；文案永远正向。
- **排行榜工程实现**：客户端结算时上报 `{userId, date, count, ms, mode, city}`；服务端用 **Redis Sorted Set**（每个 `榜单×日期×地区` 一个 ZSET：`ZINCRBY` 记分、`ZREVRANK` 查名次、`ZRANGE` 取 Top/邻近区间，千万级用户毫秒级响应），按时区滚动建 key + TTL 过期即天然实现日重置；地区用 IP/GPS 粗定位到城市。防作弊：端上计数置信度分 + 单日封顶（3000）+ 服务端频率异常检测（>8 跳/秒剔除）+ 影子封禁。Atom 弱网时缓存上次榜单、结算后异步上报。原型为按日期播种的确定性示意数据。

## 4.5 对标研究：任天堂《Jump Rope Challenge》

疫情期间任天堂员工居家开发的免费小游戏，Joy-Con 模拟跳绳，画风是极简儿童卡通。已吸收进本设计的机制：

| JRC 的做法 | 我们的转化 |
|---|---|
| 每日默认 100 下的固定小目标，可在设置里调高 | 50/100 两档 + 自由跳，默认记住上次选择 |
| 兔子角色陪着玩家一起跳、负责计数 | 吉祥物 Bono 同步蹦跳（"陪练"定位一致） |
| **跳满 100 下解锁一张新背景**（小猫、海滩、月球等实景图） | 每次达标解锁一个新场景，跳绳中每 10 下在已解锁场景间轮换 |
| **方向键左右切换兔子换装**，更新追加了马里奥/林克等任天堂角色服装 | Bono 换装按**累计跳数**解锁（100/300/500/1000/2000），首页左右箭头切换 |
| 每日成绩记入时间线，单日最高记录到 1000 下封顶 | 打卡日历 + 累计总数常驻首页；单日封顶防刷（工程项） |
| 双人模式（各持一只 Joy-Con） | 第一版不做，列入二期（双人同框摄像头计数技术上可行） |

JRC 没做而我们补上的：连续打卡 streak、星星软货币、随机彩蛋（可变奖励）、每日重置的全球/同城排行榜。JRC 教给我们最重要的一课是**克制**——它没有排行榜、没有内购、没有推送，靠"每天 100 下 + 一点点收集欲"就让人天天回来。

## 5. 双端设计：手机 App vs Atom（466×466 圆屏）

Atom 是 466×466 像素的小圆屏设备，屏幕信息必须极度取舍。原则：**屏上只放"跳的时候必须看的"，其余全部交给语音和边缘光。**

| 状态 | 手机 App（竖屏，信息全量） | Atom 466×466 圆屏（信息取舍） |
|---|---|---|
| 待机 | 打卡条、星星、目标选择、大按钮 | 一句话提示 + 目标 chip（点按循环切换）；欢迎语用语音 |
| 准备 | 相机取景器 + 人形轮廓框 | **无取景器**（屏太小没意义）→ 边缘光：橙色呼吸 = 请站位，变绿 = 锁定；语音引导 |
| 跳绳中 | 大计数 + 进度环 + Bono + 相机小窗 | **只留三样**：中央超大计数（约屏高 40%）+ 贴边环形进度 + 迷你 Bono；每 10 下语音报数 |
| 结算 | 成绩、星星、打卡日历、解锁、分享、运营位 | **两页翻页**：第一页成绩/星星/连签/解锁，点按翻到第二页大二维码 → 手机扫码看详情 |

- **圆环**贴屏幕边缘是圆屏的天然优势：**每 50 下一圈**，跳满即清零、从头再画；累计的圈数不靠环表达，靠**星星**——每跳满 50 就多点亮一颗 ★，一眼可数。
- Atom 跳绳中布局：顶部一行小字计时 → 大数字 + 旁侧 🌟 目标倍数星 → 下 3/5 纯粹的火柴人。
- **阶段策略：Atom 设备端优先**，手机端设计保留但开发暂缓（原型中经 `#phone` 入口可看）。
- **图标规范**：设备端不用 emoji（渲染依赖系统字体、风格不可控），统一用**单色 SVG 图标**（火苗/星星/奖杯/时钟/礼物/列表），跟随品牌色着色（火苗用暖橙呼应"燃"，星星用绿）；★ 等文本符号可用（可控着色）。
- **按钮可点击性**（466px @ ~326ppi，9mm 触控目标 ≈ 115px）：① 屏上按钮只做次要入口，主流程靠站位/语音免触屏；② 主按钮（开始/再跳一轮）做大做满（高 ≥ 80px）；③ 次按钮（目标/记录）≥ 60px 且相互留 ≥ 0.8em 间距防误触；④ 大面积页面用**全屏点按**代替小按钮（结算翻页、记录页返回）；⑤ 按压反馈用直切（缩放 95% + 提亮），15fps 下 transition 无效；⑥ 可导航的入口带 "›" 记号与描边，与纯信息区分。
- **统一字阶（466 屏，Atom 官方标准 6 档：18 / 22 / 24 / 28 / 32 / 36，远读优先）**：**18px** 微标注/角标（引导箭头 ›、PB 徽章、海报小字）→ **22px** 辅助提示（翻面提示、准备页提示、暂停副文案、海报评级）→ **24px** 正文/列表/次按钮（记录行、榜单行、设置项、模式副文案、page-cta、计时）→ **28px** 主按钮/强调（Start、chip、页卡标题、PB 行、星星行、toast）→ **32px** 标题/主状态（二级页标题、模式标题、准备状态、结算标签）→ **36px** 庆祝覆盖层。数字展示档（数字专属，不占 6 档文字标准）：海报 40 / 卡片&结算大数 **56** / 大计数 **96** / 倒计时 **136**。原型中以 CSS token（`--t18…--t36`、`--n40…--n136`）落地，屏上文字只允许取这 6 档。
- **中英双语**：全部 UI 文案（含教练语音/toast/结算/设置）收敛到 `I18N` 双语字典，EN 为讨论主版本（默认英文），控制条 EN/中文 一键切换，`?lang=zh` 直达中文；语音随语言切换音色（zh-CN / en-US）。场景、装扮、勋章名均有双语。
- **页面骨架规范（统一二级页/滑动页版式）**：标题钉在顶部安全区（顶部留 2.6–2.7em，圆弧最窄区标题需 ≤5 个汉字 / 8 个英文词符）；内容在中区弹性居中（`hbody`，超高优先裁行数而非溢出）；提示/元信息钉底部 7.5%（圆底极窄，仅放 ≤22px 单行短句）；行式内容统一左右对齐 + 细分隔线（同首页）。覆盖层背景全不透明（半透明在小屏上底层文字会透出形成"脏"感）。
- **状态与超时策略（空 / 边界 / 极限）**：
  - **空状态**：首页显示真实零值（连续 0 天 / 今日 0 / PB —），Start 是唯一强 CTA；记录页与榜单页有引导文案（"还没有记录，跳一轮就有啦"）；最佳战绩未产生的项显示 "—"。
  - **计数累积**：**单轮计数从 0 开始**（一轮对应一个目标，"再跳一轮"重新起算）；**今日累计跨轮累加**（首页"今日"、排行榜、打卡记录、结算页"今日累计"行都用累计值），每天 0 点重置。中途退出不丢数据：结算即落档。
  - **超时链路**：开跳**不做站位校验**——选完模式直接 3·2·1·**BodyPark**（品牌口号发令）开跳；跳绳中离开画面 → 立即暂停（停表），5s 未回 → 自动结算（成绩落档）；结算页 45s 无操作 → 自动回首页。
  - **极限保护**：单轮 30 分钟 → 语音+toast 提醒休息；60 分钟 → 强制结算（儿童过练保护，成绩照常落档，可立即再开一轮）；计数 ≥1000 → 数字降档 96→68px 防溢出；星标 >4 颗收敛为 ★×N；1 分钟测试上限本身 2 分钟，不受此约束。
- **设备约束：屏幕刷新率 10–15fps 波动**（demo 提供 10/13/15 三档模拟）。动效设计原则随之调整：① 过渡动画一律**状态直切**（300ms 的 tween 在 15fps 下只有 4 帧，直切更干净）；② 旋转类光效放慢转速（每帧位移 < 5°，避免可感知的跳变）；③ 脉冲效果用**两态闪烁**替代连续渐变；④ 每跳的数字弹跳用 3 帧内完成的离散关键帧；⑤ 计时等文字信息 2Hz 刷新即可。原型中 Atom 圆屏默认以 15fps 量化模拟（控制条可切回 60fps 对比）。
- **Atom 信息架构（三层）**：
  1. **系统入口卡**（Atom OS 层）：Bono + 每日跳绳 + 连胜天数，点按进入 APP；
  2. **首页卡组**（横滑三张，圆点指示）：**首页卡**（连续 N 天一行式 → 今日 → PB 行 → 累计天数+星 → Start + 设置）→ **打卡记录页** → **全球排行页**（成就/勋章卡 **P1 暂缓**，先聚焦打卡 + 排行两个钩子）；
  3. **二级页面**：历史打卡（日期 · Day x · 次数 · 用时）、排行榜（全球/同城）、最佳战绩（单轮/1'/2'/单日）、设置（勋章墙随勋章体系 P1 暂缓）。
- **点开始 → 模式选择页**：「限时跳」（1'/2' 可切，倒计时冲刺）或「不限时」（跳多少算多少，计入每日任务）。
- **勋章体系（P1 暂缓，规则保留备用）**（零成本，全部由现有数据计算）：连胜 7/21 天、累计 1000/10000、1 分钟 120、单轮 200、单日 300、猎中隐藏数字——覆盖坚持/总量/爆发/趣味四个维度，让不同类型的用户都有可追的下一枚。动力三件套 = **积分（星星）+ 勋章 + 排行榜**：积分是即时反馈（当次就有），勋章是中期里程碑（数周可达），排行榜是每日竞技（每天重置）——短中长三个时间尺度各有一个钩子，支撑"每天都想动一动"。
- **漫画放射光背景（燃起来，分级点火）**：跳绳中是**纯黑舞台**——前 50 下背景全黑，安静蓄力；跳满第一圈（50 下）起出现轻微的**暖橙色**放射光芒（漫画集中线）；满两圈光芒变亮变密，满三圈全面燃烧——底部火光 + 亮度脉冲 + 转速加快。火焰刻意用暖色跳出黑白灰绿品牌色：**黑色舞台上唯一的暖色 = 你烧起来的努力**；达标后计数数字也转为暖橙色呼应。
- 数据同账号双端同步；三种使用形态都成立：只用手机 / 只用 Atom / 两个同时开（同时开时状态实时互通，手机可当 Atom 的详情屏和遥控器）。

## 6. 关键技术点（供研发评估）

1. **姿态估计**：端上推理，MoveNet Lightning 级别（>30fps on 中端手机）；Atom 若有 NPU 则跑更高精度模型。
2. **跳跃判定**：髋部关键点 y 坐标做带通滤波 → 峰值检测 → 状态机（腾空/落地）；典型跳绳频率 1.5–3 次/秒，以此设频率窗口过滤误判。
3. **延迟预算**：摄像头采集→推理→计数→音效反馈全链路 < 100ms，音效走低延迟通道（iOS: AVAudioEngine；Android: AAudio/Oboe）。
4. **隐私**：视频帧全部端上处理，**不上传任何影像**，只上传计数结果。首次启动用一句话讲清楚（这也是家长关心点）。
5. **弱光/遮挡兜底**：置信度连续走低时，UI 提示"往后站一点/开个灯"，而不是默默漏计。

## 7. MVP 范围建议（先跑通闭环，两周可 demo）

**做**：今日页、准备页、跳绳中（计数 + 每 10 下换背景 + 音效）、达标庆祝、结算页、本地打卡记录、吉祥物基础动画（待机/跳/庆祝三态）。

**不做（第二期）**：星星商城与换装、补签卡、实物奖品运营位、Atom 端语音播报、分享海报。

### 5.1 实时骨骼火柴人渲染（与 AI 管线的对接契约）

跳绳中下 3/5 的火柴人由**实时骨骼关键点驱动**（用户即火柴人，Bono 退居其余页面）。对接契约：

- 接口：`AtomSkeleton.feed(pts)`，`pts` 为 33 关键点数组 `[{x, y, v?}]`，MediaPipe Pose 拓扑，坐标归一化 0–1（原点左上、喂入前完成镜像），建议 ≥15Hz；500ms 无数据自动回落到内置模拟动作。
- 渲染：Canvas 466×466 @15fps 与屏幕刷新率一致；白色圆头 + 线条四肢（纯火柴人风格），手腕/脚踝品牌绿点。
- **触地涟漪**：双踝下行穿过地面线（y≥0.872，240ms 去抖）判定触地，在触地点沿屏幕底部弹出**由下向上扩散的绿色半圆波纹**（双环递进、逐帧衰减）——把"每一次落地"变成可感知的节拍反馈。
- 计数管线独立：骨骼流只管渲染与动效，计数仍走 AI 团队的判定结果。

## 8. 商业与增长设计（好推广 · 好卖 · 上瘾 · 口碑）

**好卖 = 一句话理由**：绑定体测刚需——"每天 3 分钟，体测跳绳达标"。P0 功能：**体测评级模式**（1 分钟测试按年级/年龄段套国家体质测试标准出"及格/良好/优秀/满分"）；门店 30 秒免触屏 Demo；**多用户家庭档案**（一台设备全家用）；结算炫耀海报 + 挑战链接。

**上瘾 = 短中长三钩子 + 损失厌恶**：积分（即时）/ 勋章（中期）/ 排行榜（每日）已就位；补：**连胜保护**（补签卡 + "连胜还剩 6 小时"设备/手机提醒）、**动态每日目标**（按近 7 天表现自动调）、**亲友异步 PK**（熟人竞技召回强度远超陌生榜）、Bono 牵挂感（弱化版宠物养成，儿童伦理边界）、月度赛季（限定勋章/场景/换装）。

**口碑 = 超预期 + 零讨嫌**：计数精度是地基；**成长周报**（进步曲线/超过同龄人比例/卡路里，家长价值证明兼转发素材）；零讨嫌承诺（无广告、无内购坑、影像不上传）；变强路径（姿势纠错、花样跳绳课程）。

## 9. 设计评审：改进项与缺失维度

**改进项**：① 计数精度未实测（最高风险，先做技术 spike + 真人实测）；② 首次使用引导缺失（Bono 30 秒示范站位）；③ 结算页信息过载（改逐条弹入节奏）；④ 榜单冷启动需虚拟陪跑/同龄段匹配策略；⑤ 定制语音包要早做；⑥ 中断恢复逻辑未定义。

**缺失维度**：多用户/家庭档案；年龄分层（目标/标准/文案/语音）；健康数据（卡路里/时长/心率）；儿童防沉迷与热身引导；账号云同步（现为本地存储）；设备端定时提醒召回；儿童隐私合规与摄像头指示灯；度量体系（北极星指标建议：**每日完成率**）与运营后台。

**优先级**：P0 = 计数精度、体测评级、首次引导、周报+海报；P1 = 多用户、连胜提醒、动态目标、亲友 PK、语音包；P2 = 赛季、教学内容、Bono 养成、健康数据。
